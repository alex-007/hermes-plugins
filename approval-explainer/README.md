# Approval explainer

A default-profile plugin for classic Hermes CLI, Ink TUI (`hermes --tui`) and Matrix. Smart automatic approvals and ordinary commands do not generate explanations. ACP, Telegram and other custom transports are unsupported. Matrix wraps the profile-scoped adapter after plugin discovery: synchronous generation runs in a worker thread; the explanation is prepended to the same exec-approval message, retaining the raw command, original trigger reason and core reactions/authentication. Failure yields a neutral fallback; incompatible internal APIs retain stock behavior with a warning. Other profiles are excluded.

The classic CLI modal callback calls the existing `approval` auxiliary model for a Russian description. The panel keeps the normal approval choices visible and adds a separate `Полное пояснение` choice; selecting it opens a paginated view with Previous/Next page, `К подтверждению` to return, and Deny. Viewing never approves a command and the original deadline continues. The complete generated explanation is reachable without clipping. The generated explanation is no longer cut at 700 characters; the model generation cap (`max_tokens=400`) remains explicit. The original command/script safety caps remain in force. Plain input()-based approvals retain scrollback explanation. A narrow/short terminal may truncate the preview, but not the full-view content. This uses guarded runtime patches of the classic CLI callback, selection handler and renderer, not core source edits; internal API changes may require a plugin update. It does not alter commands, policies, choices or approval decisions. One extra model request per human CLI approval; no system-prompt additions. Deadline: 8 seconds, then a neutral fallback and the original prompt. Concurrent/hung explanation work is bounded to one worker. Late text is discarded.

Ink TUI decorates the real gateway approval notification on the agent thread, before the prompt reaches the renderer. The description contains the explanation followed by the original trigger reason; the pending queue keeps the same presentation text for reconnects. Commands, IDs, policy flags, choices and the core resolver are unchanged. Generation runs only when the core publishes a new human prompt, not for coalesced followers. The existing bounded generator and fallback are shared with CLI/Matrix. A guarded runtime wrapper covers both aliases of `_await_gateway_decision`; incompatible APIs retain the stock prompt. Restart the gateway process serving TUI after installing this version; restarting only the Node renderer does not reload an in-process plugin.

Explicit absolute external script paths are read without executing them, bounded to 12 KB, regular files only, no final symlinks. Relative paths and protected credential files are not read. Input and output are secret-redacted. Text is explanatory model output, not a guarantee of safety.

Installed in `$HERMES_HOME/plugins/approval-explainer/`. Enable/disable with `hermes plugins enable/disable approval-explainer`. Takes effect in a NEW CLI process; no gateway restart needed for CLI functionality. Requires `plugins.isolation: in_process` for rendering with the host UI; isolated plugin-host rendering is not supported. No core checkout edits, so normal updates do not need a patch reapplied.

Tests: `hermes --run-module unittest discover -s "${HERMES_HOME:-$HOME/.hermes}/plugins/approval-explainer/tests" -v`. The source-path smoke fixture in tests can be run through a bootstrapped Hermes runtime in a PTY; it asks once/deny for a harmless print command without executing that command or storing permissions.
